## 1. Schema, identities and fixture boundaries

Each line in `eval-cases.jsonl` is an independent JSON object. Required fields: `case_id` (unique immutable case key), `family`, `score_group`, `focus_skill`, `role`, `prompt`, `allowed_skill_set` (pre-fixed selection oracle; may include two justified Skills), `repetitions`, `input_mode` (`typed_skill` or `text_only`), `typed_skill` (name or null), `baseline_pair_id` (ID or null), `coverage_skills`, `fixture` and `oracle_id` (exact match to section 3). Do not append mutable result/status fields to a case. Case IDs and oracle IDs are globally unique.

**Prompt-only contract:** Evaluated agents receive `prompt` and the common applicable instruction context, *never* `focus_skill`, `allowed_skill_set`, `oracle_id`, scorer commentary, other results or this oracle file. Except typed explicit runs, the candidate receives no skill name hints. The fixture fields describe future evaluation-side controls; they grant no permission to run Bash, modify a repository or create files.

**Candidate and baseline:** `EXP-XX` uses native *typed* Skill input with exact name/path from source S; the paired `BASE-XX` uses the **byte-identical task prompt and role** with no typed input and without the eleven candidate Skills. Only that intended intervention varies. The actual native typed-input payload is inspected against supported runtime schema during future capability smoke; a literal string `$skill` is not equivalent by default. The paired cases have explicit symmetric `baseline_pair_id`.

**Role/context inventory fixed in plan, actual bytes pinned at execution:** both environments receive identical applicable `AGENTS.md` (expected current common blob `5859c87bf3240a938a64dbf743f9bcea28975194`), `docs/workflow/development.md` (current common blob `5674c202b06d95e8401d593f7ca896924c6f87e5`), relevant memory/workspaces/security procedures, role briefs, and approved exact task contracts at their applicable revisions. Select only relevant canonical material, not arbitrary historical documents; candidate and baseline must see the *same* chosen normative bytes and task data. Recorder must verify actual runtime-selected instruction files and Git blobs. System/user Skills inventory and collisions are captured before test. An uncorrectable context collision makes the comparison **CONTAMINATED/BLOCKED**, never a false candidate benefit.

**Future fixture boundary:** These S1 cases are safe synthetic text prompts and require no file writes. Future mutation-capable negative fixtures, including before/after inventory and denied actions, belong to a separately Stage-READY W-S3 with exact absolute disposable root, recorder-only output location, OS user/sandbox restrictions, network/credential controls, and safe cleanup. No blanket `/tmp/*`, global skill install, or use of unreviewed code is authorized here.

**Fixed run sequence:** Use the **literal JSONL file order**, with each `case_id` executed in fresh session `repetition_index=1…repetitions` consecutively. First twenty-two records alternate `EXP-01`/`BASE-01` … `EXP-11`/`BASE-11`, then implicit, unrelated, five fixed near, two additional near and sixteen safety cases. Sample IDs are `case_id + /R + repetition_index`; these form an unambiguous future ordered run list. Do not change scheduling, prompts, allowed sets or case ordering after inspecting outcomes.

**Eligibility, invalid runs and reruns (precommitted):** Count one fixed denominator slot per intended run; a valid assessed observation requires a complete native request/response, model/config/role/cwd, exact candidate S/Skill blobs, relevant Skill inventory, attributable output/exit/trace and independent recorder evidence. Wrong task output, wrong routing, legitimate sandbox denies and model-level errors are scored against the oracle, not silently classified as infrastructure loss. An infrastructure failure that prevents observation is retained as **INVALID/BLOCKED** (never PASS), and the affected metric cannot pass on a silently reduced denominator. No selective retries/replacements. A complete affected-group rerun is permitted only under separately documented pre-run authorization with the full original and rerun traces retained, and only after its cause and material config differences are assessed; no favorable cherry-picking. Changed source/oracles/conditions trigger new pinned inputs and affected assurance, not retroactive editing.

**Scoring hierarchy and statuses:** Independently distinguish catalog discoverability, accepted explicit typed input, attributable implicit Skill access or runtime selection, oracle-based task behavior, forbidden tool attempts and actual filesystem effects. `PASS` requires all applicable measured predicates; `FAIL` denotes confirmed mismatch; `NOT_RUN` no execution; `NOT_OBSERVABLE` unavailable evidence channel; `BLOCKED` missing mandatory prerequisites, context contamination or insufficient capability; `INVALID` is a retained technical attempt needing documented disposition. Do not infer 'no wrong Skill activation' from absent events before observer positive+negative completeness smoke.

**Per-Skill differentiated benefit:** Evaluate candidate vs baseline on required-step completeness, critical omissions, fail-closed authority, evidence attribution and task-specific reproducibility. Use side-by-side raw task artifacts and independent rubric; do not infer benefit from naming a Skill. A Skill without any concrete differentiated utility triggers **REWORK** under the accepted Spec even if routing thresholds are met. This rubric does *not* require numeric dominance of each candidate metric.

## 4. Native observer-capability smoke — future local execution ONLY

**S1 status: NOT_RUN.** Under a later approved W naming actually verified absolute disposable paths and dedicated unprivileged recorder/evaluator identities, perform this non-scored smoke **before** any of the 94 assessed runs. A toy Skill and permission checks must remain inside that authorized fixture; source S and oracles are read-only and are not under evaluated-agent control.

1. **Version/schema and common context:** record real Codex version, App Server/protocol support, runtime model/settings, root/nested cwd, common `AGENTS.md` and procedures, actual global/user/system Skill inventory, and candidate/baseline identity. Do not assume today's documented API is implemented locally.
2. **Discovery:** obtain structured `skills/list` with real supported parameters for root and nested cwd, check expected eleven enabled names+paths against source S; static files are not catalog PASS.
3. **Explicit control:** submit a supported native typed Skill item in `turn/start` (or actually documented equivalent), verify request acceptance and attributable Skill path/version plus independently useful toy output. A plain text `$skill` mention does not replace typed evidence.
4. **Implicit-positive control:** submit a fresh text-only toy task; capture a relevant native event or independently observed path-read linked to the reviewed source blob and correct task behavior. Keep behavioral success separate from unexposed internal model ingestion.
5. **Implicit-negative control / completeness:** submit unrelated task; prove that the observer sees all relevant potential Skill activations/reads under this runtime. The ability to observe a positive activation alone does not demonstrate comprehensive negative coverage. Missing completeness means `NOT_OBSERVABLE/BLOCKED` for zero-activation claims.
6. **Rights and effects:** independently verify executable identity, sandbox constraints, tool permissions, network and credentials, before/after Git/filesystem inventory and denial evidence. Git worktrees are not an OS permissions boundary. Any unsupported assumption makes mutation-capable fixtures BLOCKED.
7. **Decision:** capture the actual schema, raw redacted trace and scope of what it proves. If mandatory explicit, implicit-positive or implicit-negative evidence is unavailable, STOP before scored runs; report `NOT_OBSERVABLE/BLOCKED` and request Owner disposition or authorized revision. No invented PASS, installation, force-push or privilege escalation.
