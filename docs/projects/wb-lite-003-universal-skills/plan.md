### 5.2 Authoring / evaluator / recorder trust design (R1-F02)

1. **Author session and source freeze:** Coder creates only W-owned Skills in its authorized non-live checkout, without running them. A distinct read-only reviewer checks trust, paths, provenance, forbidden commands and metadata before native tests. The independent Git recorder first pins the inspected **S2 Skill snapshot** (exact commit and eleven Skill blob IDs), rejecting partial/uncommitted/dirty content; this snapshot is not final S. After W-S3 is separately committed and Stage Critic READY, the recorder verifies unchanged vetted Skill blobs and pre-fixed corpus/oracles and designates the exact full-tree commit containing that approved W as final **S**, before releasing the byte-identical Skill copy for evaluation. Any subsequent Skill or normative W change requires a new S and affected checks. A Git commit is an integrity identifier, not an OS permissions barrier.
2. **Separated evaluator snapshots:** under an approved W, a separate controller/recorder materializes two minimal task environments: **candidate** containing byte-identical vetted `.agents/skills` files from exact S, and **baseline** with those eleven files entirely absent. Both have equivalent benign task inputs, tested cwd root/nested layout, runtime/model settings and fresh ephemeral session context. Do **not** expose full source repo/history or `eval-oracles.md` to the evaluated agent. Capture the system/user/admin Skills actually visible; if they overlap or cannot be kept equivalent, mark that comparison contaminated/blocked instead of altering a global installation. The evaluator's candidate directory may be a Git repo for normal Codex discovery, but Git worktree separation is not a security boundary.
3. **Principals and rights:** evaluated Codex runs in a fresh least-privilege identity/session against **read-only** Skill/source files and only the **specifically authorized disposable fixture/output directory** writable when a case needs it; network and privileged credentials disabled wherever the harness/OS permits. It has **no write authority** over the accepted Spec/P, original source S, oracle, scorer, recorder logs or GitHub. A policy controlling filesystem/network access must be actually established and tested; if it cannot be, affected unsafe tests are BLOCKED rather than claimed isolated.
4. **Independent raw-event custody and scoring:** a separate recorder (not the evaluated agent, not `skill-evaluation` itself) stores unmodified/secret-redacted raw structured App Server/`codex exec --json` observations and before/after state in a **W-listed recorder-only absolute evidence destination**, hashes the snapshots and links summarized findings via the already listed `docs/changes/WB-LITE-003/test-evidence.md`. A separate independent Verifier examines that evidence against **committed pre-run `eval-cases.jsonl` and `eval-oracles.md`**, and authenticates that S was unchanged. The tested agent sees task prompt/fixtures, **never the scored oracle or results**, and cannot author its own acceptance verdict.
5. **Run validity:** each evaluated and baseline case is a new native turn/session with documented model/version/sandbox/cwd, exact prompts, system/user Skill inventory, observed trace and case ID. Invalid/failed runs are retained; eligibility, rerun rules and selection oracle are fixed before scoring. Recorded trace absence can never be silently called a skipped Skill when the observer lacked coverage. W must authorize concrete absolute paths and fixture cleanup separately; no shared default `/tmp` authority.

**Neither P nor the accepted Spec mandates invisible vendor internals, but both demand truthful observed claims.** Source/fixture copies can prove byte identity and outputs; without an event or observation capable of distinguishing implicit selection, mandatory selection acceptance is **BLOCKED**. An alternative path requires Critic/Owner disposition, not a weaker hidden threshold.
